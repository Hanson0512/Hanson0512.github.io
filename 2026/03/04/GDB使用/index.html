GDB使用

本篇内容主要介绍一些pwn工具的使用（方便后续的理解和调试

例题1 GNU-debug

先以ns2025的一道例题引入

首先运行文件（./)

然后run 靶机

第一关需要我们找到r12的值

使用指令：i r （information register）查看寄存器当前的值（pwndbg能够直接看到）

第二关需要查看内存的值

gdb中使用“x”命令来打印内存的值，格式为“x/nfu addr”。含义为以f格式打印从addr开始的n个长度单元为u的内存值。参数具体含义如下：

n代表想要查看多少个内存单元即从当前地址开始计算，每个内存单元的大小由后面的u参数指定；
f表示显示格式，
s表示字符串形式，
i为指令形式；
u指定内存单元大小，
b(一个字节)
h(双字节)
w(四个字节)
g(八字节)默认为w；

拓展：tel address能够将地址所存指针所指向的内容打印出来

命令 功能特点 是否跟随指针 输出示例
tel addr Pwndbg 扩展，智能显示 ✅ 会显示指针指向内容 0x600000 —▸ 0x7ffff7fe4000 ◂— endbr64
x/s addr GDB 原生命令，显示内存内容 ❌ 只显示原地址 0x600000: "Hello world"

第三关需要我们设置断点让程序停下来

当调试汇编程序，或者没有调试信息的程序时，经常需要在程序地址上打断点，方法为b *address。

第四关需要在对应地址进行赋值，使用指令：

set *0x7fffffffd994 = 0xdeadbeef

（如果要改参数： set var b =)

几个比较常用的指令：

首先就是设置断点了，有几种方式：

在程序地址上打断点：b *address

在文件行数打断点： b number

打完断点之后可以输入r，执行程序

然后通过下面的三种指令逐步看程序的变化：

next(n):单步跳过 执行当前代码 跳到下一行（如果指向函数则执行完函数）

step(s):单布步入 （可以钻进函数内部）

continue(c):继续执行

注意，如果是单步走汇编的话就用ni si

查看数据：

print（p） 后面可以跟计算式，也可以跟&a用来看a的内存地址

cyclic

cyclic number 用于生成长度为number的字符串

可以使用cyclic -l （rip的）字符串，来算偏移量（这边相当于可以代替ida上直接计算）

能看到从输入数据起点到 RIP 被覆盖位置的偏移量

stack

用cyclic后配套使用的是stack指令，可以看rsp高位地址的number个地址的情况（用来看rip的）
